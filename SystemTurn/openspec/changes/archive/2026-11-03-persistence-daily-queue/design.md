# Design: Persistence and Daily Queue

## Technical Approach

Hexagonal mapped adapter. The domain (`Turno`, `TurnoRepository`, exceptions) stays free of Spring/JPA. A JPA entity + Spring Data repository + adapter in `infrastructure` implement the port. `TurnoService` stays a POJO: every use case has exactly one write, and consistency comes from the DB (`UNIQUE(fecha, numero)` + `@Version`), not from a service-level transaction or `synchronized`. Covers specs `ticket-persistence`, `daily-queue`, `concurrency-conflicts`, `demo-seed`.

## Architecture Decisions

| Decision | Choice | Rejected (tradeoff) |
|---|---|---|
| Transaction boundary | Adapter is NOT `@Transactional`; each port call runs in Spring Data's per-method tx and uses `saveAndFlush`, so commit/flush failures surface inside the adapter's `try` and get translated there | `@Transactional` on `TurnoService` (Spring in application layer); transactional decorator/`TransactionTemplate` wrapper (violation surfaces at commit, outside the retry loop; more code); `@Transactional` adapter (same commit-outside-`try` problem) |
| Number assignment | `maxNumero(hoy)+1` → insert; adapter maps `DataIntegrityViolationException` → `NumeroDuplicadoException`; service retries, max 10 attempts, then `ConflictoException` | `synchronized` (single JVM only); counter row + pessimistic lock (needs service tx) |
| Stale writes | Domain carries opaque `Long version`; adapter maps `ObjectOptimisticLockingFailureException` → `ConflictoException` (409). No auto-retry | One silent retry (could attend a different ticket than the advisor saw) |
| Persistence model | Separate `TurnoJpaEntity` + mapper | Annotating `Turno` (couples domain to `jakarta.persistence`) |
| Day boundary | Query filter `fecha = today`; no cleanup job; past PENDIENTE untouched | Nightly job closing tickets (extra moving part, user rejected) |
| Past-day cancel rule | In domain: `Turno.cancelar(LocalDate hoy)` throws `OperacionInvalidaException` if `fecha != hoy` | Service-level check (rule leaks out of the entity) |
| Schema | Flyway `V1` + `ddl-auto=validate` | Hibernate DDL generation (unversioned) |
| Seed | `DemoSeedRunner` under `@Profile("demo")`, `@Transactional`, idempotent | Unconditional CSV load (pollutes prod DB) |

Why max 10 attempts: each failed attempt means another thread committed that exact number, and numbers only grow, so with N concurrent callers a caller fails at most N-1 times. 10 attempts deterministically satisfies the 10-thread scenario. The value is a constructor parameter (tests pass 2 for exhaustion).

## Data Flow

    Controller ─→ TurnoService(Clock) ─→ TurnoRepository (port)
                                              │
                         JpaTurnoRepository (adapter, translates exceptions)
                                              │
                         TurnoJpaRepository (Spring Data, per-call tx) ─→ H2 file

Per use case (`now = LocalDateTime.now(clock)`, read once so date and time never straddle midnight; time truncated to SECONDS):

| Use case | Flow | Errors |
|---|---|---|
| `solicitar` | loop ≤10: `n = maxNumero(hoy)+1`; `guardar(Turno.nuevo(hoy, n, hora))` | duplicate → retry; exhausted → `ConflictoException` |
| `llamarSiguiente` | `fila()` first → `atender(hora)` → `guardar` | empty → `FilaVacia`; stale → `Conflicto` |
| `cancelar(id)` | `findById` → `cancelar(hoy)` → `guardar` | missing → 404; past day / not pending → 400; stale → 409 |
| `fila`/`posicion`/`dashboard` | `findByFecha(hoy)`; FIFO by `horaSolicitud`, then `id`; `indexOf` uses `equals` by id; dashboard derives queue from one read | — |

## Interfaces / Contracts

```java
public interface TurnoRepository {
    List<Turno> findByFecha(LocalDate fecha);
    Optional<Turno> findById(long id);
    int maxNumero(LocalDate fecha);          // 0 when the day is empty
    Turno guardar(Turno turno);              // id==null → insert; else versioned update
}                                            // throws NumeroDuplicadoException, ConflictoException

// Turno: Long id (nullable), LocalDate fecha, int numero, LocalTime horaSolicitud/horaAtencion,
// EstadoTurno estado, Long version; equals/hashCode by id (identity when id is null).
static Turno nuevo(LocalDate fecha, int numero, LocalTime hora); // PENDIENTE, id/version null
```

Flyway `V1__create_turno.sql`:

```sql
CREATE TABLE turno (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  fecha DATE NOT NULL, numero INT NOT NULL,
  hora_solicitud TIME(0) NOT NULL, hora_atencion TIME(0),
  estado VARCHAR(16) NOT NULL CHECK (estado IN ('PENDIENTE','ATENDIDO','CANCELADO')),
  version BIGINT NOT NULL,
  CONSTRAINT uk_turno_fecha_numero UNIQUE (fecha, numero)
);
```

The unique index also serves `findByFecha`/`maxNumero` (leading `fecha`); no extra index.

Entity gotchas: `@Enumerated(STRING)` + `@JdbcTypeCode(SqlTypes.VARCHAR)` (Hibernate 7 H2Dialect expects native `enum` under `validate`); `@Version Long version` must be a wrapper, because Spring Data `isNew()` uses `version == null` (primitive breaks insert vs merge); `@GeneratedValue(IDENTITY)`. `maxNumero` = `select coalesce(max(t.numero),0) ... where t.fecha = :fecha`.

409 body: `{"error":"CONFLICTO","mensaje":"El turno cambió mientras se procesaba. Actualiza e intenta de nuevo."}`. Other v1 shapes are unchanged (`Hora` already formats `hh:mm`, so seconds stay hidden).

| `src/test/resources/application-test.yml` | `jdbc:h2:mem:turnos-${random.uuid};DB_CLOSE_DELAY=-1` (fresh DB per context, so `@DirtiesContext` resets ids) |
| `TurnosConfig` | `Clock.system(ZoneId.of(timezone))`; `TurnoService(TurnoRepository port, Clock)`; CSV load removed |

`CsvSeedLoader` becomes a pure parser: `List<Turno> parse(Resource, LocalDate)`, sorted by time. CSV renumbered in arrival order: 1-5 ATENDIDO, 6 PENDIENTE, 7 CANCELADO, 8-11 PENDIENTE.

Frontend: `request()` maps `CONFLICTO` to a friendly message plus `error.refreshable = true`. `AsesorView`: on refreshable, `await refreshDashboard()` and THEN set the message (refresh clears errors); hide "Reintentar" for refreshable errors. `ClienteView`: `ejecutar` takes an optional `alConflicto` callback; `onCancelar` passes one that runs `consultarTurno(turno.id)` and calls `setTurno`, keeping the message. The past-day not-found case needs no change ("No encontramos ese turno.").

| Integration | Unique constraint → `NumeroDuplicado`; stale version → `Conflicto`; round trip with seconds | `@DataJpaTest` (Flyway runs, `validate` checked) |
| Integration | 10 concurrent `solicitar` → exactly 1..10 | `@SpringBootTest` + latch |
| Integration | API v1 contract + demo seed + `T-012` | MockMvc, fixed Clock at 09:00 Bogota |
| Frontend | `CONFLICTO` → friendly message + `refreshable`; other errors unchanged | Vitest node env, `vi.stubGlobal('fetch')`; views checked manually |

## Threat Matrix

N/A. This change has no routing, shell, subprocess, VCS/PR automation, executable-file classification, or process-integration boundary.

## Migration / Rollout

New DB file only; Flyway creates the schema on first start. Rollback means reverting the PR and deleting `data/`.
