# Exploration: postgres-adapter

Make PostgreSQL (AWS RDS later) the production database so the API can run as multiple stateless containers on ECS Fargate. Terraform/AWS is out of scope; the app config must be ready for it.

## Current state

- Boot 4.1.2, Java 17. Datasource `jdbc:h2:file:${TURNOS_DB_PATH}`; H2 is `runtime` scope.
- Flyway V1; Hibernate `ddl-auto: validate`.
- `JpaTurnoRepository`: non-transactional, `saveAndFlush`; maps an insert violating `UK_TURNO_FECHA_NUMERO` to `NumeroDuplicadoException` via uppercased cause-message `contains`; maps `ObjectOptimisticLockingFailureException` → `ConflictoException`.
- `TurnoService.solicitar`: `maxNumero + 1`, up to 10 retries on duplicate.
- `DemoSeedRunner`: `demo` profile, single `@Transactional`.
- Tests: `test` profile, H2 in-memory with random UUID per context; `RestartSurvivalTest` uses an H2 file.
- No actuator, no Docker/compose files, no Postgres dependency.

## Findings

### 1. Dependencies (Boot 4.1.2 managed versions: Flyway 12.4.0, pgjdbc 42.7.14, Testcontainers 2.0.5)

- `org.postgresql:postgresql` (runtime)
- `org.flywaydb:flyway-database-postgresql` (explicit; Flyway 10+ split database modules — harmless if also transitive)
- `spring-boot-starter-actuator`
- Test: `spring-boot-testcontainers`, `org.testcontainers:testcontainers-postgresql`, `org.testcontainers:testcontainers-junit-jupiter`
- Testcontainers 2.x class: `org.testcontainers.postgresql.PostgreSQLContainer`; `@ServiceConnection` in `org.springframework.boot.testcontainers.service.connection`.

### 2. V1 portability

V1 runs unchanged on Postgres: `BIGINT GENERATED BY DEFAULT AS IDENTITY`, `DATE`, `TIME(0)`, inline `CHECK`, named `UNIQUE` are all valid. Hibernate `validate` compares JDBC type codes, so `time(0)` is fine. Do not edit V1 and do not add vendor-specific migration folders. Only difference: Postgres stores the constraint name lowercase (`uk_turno_fecha_numero`); H2 uppercase.

### 3. Constraint-name detection

Works today by accident (message is uppercased before comparing). Harden: walk the cause chain for Hibernate `ConstraintViolationException`, require kind `UNIQUE`, compare `getConstraintName()` case-insensitively (`contains`/`endsWith` for schema-qualified or quoted names); keep the message check as fallback. Both DBs report SQLState 23505. What `getConstraintName()` returns on H2 is unverified — tests on both DBs must settle it.

### 4. Test strategy

| Option | Pros | Cons |
|--------|------|------|
| A. All tests on Postgres | Full parity | `./mvnw test` needs Docker; slower; Docker unreliable on this machine |
| B. Everything on H2 | Fast, no Docker | No Postgres proof — the exact risk of this change |
| **C. Hybrid (recommended)** | Fast default + real Postgres proof where it matters | Two test configurations |

Postgres set (`@TestConfiguration` with `@Bean @ServiceConnection PostgreSQLContainer`, image matching the RDS major): repository contract (reuse `JpaTurnoRepositoryTest` cases), `SolicitarConcurrencyTest`, restart survival (two contexts, one container), Flyway + `validate` smoke.

Gotchas:
- A shared container breaks per-context isolation → explicit cleanup in `@BeforeEach`.
- `@Testcontainers(disabledWithoutDocker=true)` doesn't apply to a container bean → custom condition using `DockerClientFactory.isDockerAvailable()`; skip locally without Docker.
- CI must FAIL (not skip) without Docker (e.g. `requireDocker` property) — lands with `infra-cicd`; document now.

### 5. Local dev

| Option | Pros | Cons |
|--------|------|------|
| **`compose.yaml` + `application-local.yml` (recommended)** | Same DB as prod; nothing dev-only in the jar | Needs Docker running |
| `spring-boot-docker-compose` | Auto-starts DB | Dev-only dependency in jar; more magic |
| H2 dev profile | No Docker | Two databases to support |

Recommendation: H2 → test scope only. With H2 on the runtime classpath and no datasource URL, Boot silently starts an embedded in-memory H2 — a forgotten `SPRING_DATASOURCE_URL` would lose data without error. Test-only H2 turns that into a fail-fast. **Real fork — user decides.**

### 6. Deployment config

- Datasource: `application.yml` holds only a localhost placeholder, no password. `SPRING_DATASOURCE_URL` / `_USERNAME` / `_PASSWORD` override via relaxed binding (password from Secrets Manager via ECS later). Local credentials only in `application-local.yml` + `compose.yaml`. TLS (`sslmode`) belongs in the URL env var (infra concern).
- Hikari: `maximum-pool-size` ~10 (env-overridable); tasks × pool < RDS `max_connections` (~112 on a 1 GiB class — from memory, unverified); `connection-timeout` ~5s.
- Flyway: `connect-retries`; Postgres advisory lock makes concurrent task startup safe; rolling deploys ⇒ expand/contract migrations.
- Actuator: expose `health` only; `management.endpoint.health.probes.enabled=true` explicitly; ALB → `/actuator/health/readiness` (not the db-inclusive `/actuator/health`); DB not in liveness.
- Graceful shutdown: `server.shutdown=graceful`, `spring.lifecycle.timeout-per-shutdown-phase` ~25s (< ECS 30s stop timeout).
- CORS already overridable via `TURNOS_ALLOWED_ORIGINS`.
- Dockerfile: belongs in `infra-app`.

### 7. Frontend alignment

No API contract change (routes, payloads, status codes unchanged). Vite `/api` proxy untouched. Deployed CORS origin is env config, not this change.

### 8. Size

~350–450 lines code/tests/config + ~150–250 docs/spec delta ≈ 500–700 (within 800).

## Affected areas

- `pom.xml`: Postgres, Flyway Postgres, actuator, test deps; H2 → test scope.
- `application.yml` (+ new `application-local.yml`): datasource, Hikari, actuator, graceful shutdown, Flyway retries.
- `compose.yaml` (new): local Postgres.
- `JpaTurnoRepository.java`: robust constraint detection.
- `src/test`: Postgres test configuration + Postgres variants (repository, concurrency, restart, smoke).
- `openspec/specs/ticket-persistence/spec.md`: "Durable storage" mentions file DB / `TURNOS_DB_PATH` → MODIFIED delta.
- `README.md`, `docs/01-current-state.md`: still describe H2 / `TURNOS_DB_PATH`.

## Recommendation

Hybrid: add Postgres/Flyway-Postgres/actuator; H2 → test scope; env-driven config with readiness for the ALB and graceful shutdown; harden unique-violation detection; compose for local dev; small Testcontainers suite (guarded locally, mandatory in CI). V1 and API untouched.

## Risks

- `persistence-daily-queue` still uncommitted — must be committed before apply.
- `demo` profile must never be active in production (two containers would race on seed).
- `MAX_INTENTOS=10`: >10 simultaneous `solicitar` may 409 (pre-existing, acceptable).
- Silently skipped Postgres tests — CI must fail instead of skip.
- Fargate runs UTC; explicit `America/Bogota` Clock should hold — seconds round-trip test on Postgres confirms.
- No Docker locally ⇒ dev fallback is an H2 profile.

## Ready for proposal

Yes, after one user decision: H2 as runtime dev profile (zero-Docker) vs test-only with compose for dev (recommended).
